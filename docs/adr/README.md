# 架构决策记录（ADR）

记录 MiStream 的重要架构决策及其权衡过程。

## 为什么写 ADR

代码能说明「现在是怎样」，说明不了「为什么不是另一种」。当半年后有人问「为什么 Spider 不跑在 Isolate 里」，ADR 是唯一能回答的地方——否则只能靠翻 issue 或者重新踩一遍坑。

## 规则

- 一个决策一个文件，编号单调递增，**永不删除、永不改写已接受的 ADR**
- 决策改变时，写一条新 ADR 并把旧的状态改为「被 ADR-XXX 取代」
- 状态：`提议` / `已接受` / `已废弃` / `被 ADR-XXX 取代`
- 涉及架构的 PR，若与现有 ADR 冲突，必须先提新 ADR

格式见 [000-模板](000-模板.md)。
