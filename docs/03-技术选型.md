# 03 · 技术选型

## 1. 选型总表

| 领域 | 选型 | 备选 | 理由 | 风险 |
| --- | --- | --- | --- | --- |
| UI 框架 | Flutter (stable) | Tauri+Web、Avalonia、Qt | 单代码库覆盖三桌面平台；渲染自绘，跨平台一致 | 桌面端生态仍弱于移动端，部分插件需自己补 |
| 语言 | Dart 3（sound null safety） | — | 随 Flutter | — |
| 状态管理 | Riverpod（code-gen 模式） | Bloc、GetX、signals | 编译期安全、无 Context 依赖、易 mock | 学习曲线 |
| 路由 | go_router | auto_route、Navigator 2.0 裸写 | 声明式、深链接、桌面窗口路由友好 | — |
| 播放内核 | libmpv | ffmpeg 自绘、VLC、ExoPlayer | HDR/AV1/DoVi、滤镜、字幕栈最完整 | dll 体积、License（LGPL/GPL 需注意链接方式） |
| 播放器封装 | media_kit（一期） | 自研 dart:ffi 绑定（二期） | 先跑通；抽象层保留替换口 | media_kit 未暴露全部 mpv 选项 |
| 数据库 | SQLite + drift | sqflite、ObjectBox、Isar | 类型安全查询、迁移工具链、桌面支持好 | 生成代码量大 |
| HTTP | Dio | http、cronet | 拦截器、超时、取消、代理、cookie jar 齐全 | — |
| DNS | 自实现 DoH（Dio 上层） | 系统 DNS | TVBox 配置带 `doh` 字段，需兼容 | — |
| JS 运行时 | QuickJS（flutter_js / 直接 FFI） | Deno sidecar、Node sidecar、Hermes | 体积小、可嵌入、可限制内存与执行时间 | drpy 依赖的宿主 API 需全部自己实现 |
| HTML 解析 | html + css_selector；XPath 自实现 | jsoup(JVM)、lxml | drpy 的 `pdfh/pdfa` 语义需要自己对齐 | 语义对齐工作量大，是兼容性主要风险点 |
| Python 运行时 | CPython 嵌入子进程 | 不支持 | 少数源使用 | 分发体积、平台构建复杂 |
| JVM 运行时 | 可选组件：外部 JRE + android shim | 内置 JRE、放弃 | 收益/成本比低，做成可选下载 | Dex→JVM 转换、android API 覆盖率 |
| 嗅探内核 | WebView2(Win) / WKWebView(mac) / CEF(Linux)，统一走 CDP | Puppeteer sidecar | 复用系统组件，体积可控 | Linux 需随包 CEF，体积 +100MB |
| 进程通信 | JSON-RPC 2.0 over stdio | gRPC、Unix socket、TCP | 无端口、无防火墙提示、跨平台一致 | 需自己做分帧与背压 |
| 序列化 | json_serializable + freezed | 手写、built_value | 不可变模型 + copyWith + 联合类型 | 生成代码量 |
| 日志 | 自研结构化 logger（JSONL 落盘） | logger 包 | 需要与 RPC 日志通道统一格式 | — |
| 崩溃上报 | Sentry（可关闭，默认关） | 自建、不做 | 桌面 native 崩溃也能抓 | 隐私：必须默认关闭 + 明确告知 |
| 打包 | MSIX + zip / DMG / AppImage | Inno Setup、NSIS | 官方工具链，签名流程标准 | 代码签名证书成本 |
| 自动更新 | 自研 updater + 静态 JSON feed | Squirrel、Sparkle | 三平台统一逻辑，可控 | 需自己做原子替换与回滚 |
| CI/CD | GitHub Actions | GitLab CI、自建 | 三平台 runner 齐全，免费额度够 | — |
| 静态检查 | very_good_analysis | flutter_lints | 更严格，早期立规矩成本低 | 初期噪音多 |
| 测试 | flutter_test + mocktail + integration_test + golden_toolkit | — | 标准组合 | — |
| Monorepo | melos | 单包、pub workspace | 多包 + 多可执行体，需要统一版本与脚本 | — |

## 2. 版本基线

M0 已固定。**单一事实来源是仓库根的 `.tool-versions`**，CI 的
`FLUTTER_VERSION` 与本表都跟着它走，三处要一起改。

| 项 | 基线 | 说明 |
| --- | --- | --- |
| Flutter | `3.44.8`（stable） | 写在 `.tool-versions`，asdf / mise 可直接读 |
| Dart SDK | `3.12.2` | 随 Flutter 分发，不单独锁 |
| 各包 SDK 约束 | `^3.12.0` | 全部 workspace 成员一致 |
| libmpv | **M1 锁定** | 届时连同 SHA256 一起写进构建脚本校验 |
| Windows | 10 1809+ | WebView2 与 d3d11va 的下限 |
| macOS | 12+ | — |
| Linux | glibc 2.31+ | 对应 Ubuntu 20.04 |

升级节奏：stable 通道，锁定次版本，季度评估一次。`dependabot` 每周开依赖
升级 PR，CI 全绿才合；主版本升级单独开 issue 评估（见
[10-开发规范](10-开发规范.md) §7）。

libmpv 之所以必须锁版本 + 校验 hash 而不是随系统漂移：播放行为的回归极难
定位，而「用户机器上的库悄悄换了」会让 issue 完全不可复现。

## 3. 需要自研、买不到现成的部分

这些是工作量与风险的真正来源，必须在计划里单独立项：

1. **drpy 宿主 API 兼容层** — `req` / `pdfh` / `pdfa` / `pd` / `pdfl` / `local` / `base64` / `md5` / `aes` / `rsa` / `gbk` 解码等。语义必须对齐现有源的实际期望，而非文档字面。
   → 对策：建「源兼容性测试集」，收集 N 个公开 drpy 源作为回归用例，每次改动跑全量。
2. **XPath/伪 XPath 解析器** — drpy 的 `pdfh` 用的是一套简化选择器语法（`a&&href`、`.class&&Text` 之类），不是标准 XPath 也不是标准 CSS。需要逐条对齐。
3. **TVBox 配置解码链** — 明文/Base64/AES 多层嵌套，且各分支实现不一致。
4. **JSON-RPC over stdio 的分帧与背压** — 见 [08-RPC协议](08-RPC协议.md)。
5. **PlayerEngine 抽象层** — 隔离 media_kit，为后续自研 FFI 留口。
6. **嗅探器的 CDP 驱动与规则引擎** — 对齐 TVBox 的 `rules` 字段语义。
7. **updater 的原子替换与回滚**。
8. **插件权限沙箱** — 见 [06-插件系统](06-插件系统.md)。

## 4. 明确排除的技术路线

| 排除项 | 原因 |
| --- | --- |
| Electron / Tauri + Web 播放器 | `<video>` 无法满足 HDR/多字幕/精细硬解控制 |
| 直接移植 TVBox 的 Java 代码 | 与 Android 框架强耦合，移植成本高于重写 |
| 在主进程内跑 Spider（Isolate） | 无法隔离原生崩溃与 OOM，违背 ADR-001 |
| 应用内嵌 WebView 做主嗅探 | 第三方页面 JS 进入主进程生命周期，稳定性与安全性都不可控 |
| 云端解析代理 | 与合规边界冲突（[01-项目概述](01-项目概述.md) §6） |

## 5. License 合规检查点

- libmpv 为 LGPLv2.1+（可配置为 GPL 构建）。**必须使用 LGPL 构建产物并以动态链接方式分发**，同时在 About 页提供完整许可证文本与源码获取途径。
- ffmpeg（libmpv 依赖）同理，注意不要启用 GPL-only 组件（如 `--enable-gpl` 下的部分 filter）。
- QuickJS：MIT，无约束。
- CEF：BSD，需附带 license。
- 第三方 Dart 包：CI 中加 license 扫描步骤，禁止引入 AGPL/SSPL 依赖。

## 6. 体积预算

### 6.1 基础包（Windows，安装后未压缩）

| 组成 | 估算 |
| --- | --- |
| Flutter 运行时 + 应用代码 | ~40 MB |
| libmpv + ffmpeg dll | ~50 MB |
| spider_js 运行时 | ~10 MB |
| 其它资源 | ~10 MB |
| **基础包合计（估算）** | **~110 MB** |

### 6.2 CI 门禁

体积预算作为 CI 检查项，分两级：

| 阈值 | 行为 |
| --- | --- |
| ≤ 120 MB | 通过 |
| 120–150 MB | **警告**——PR 可合并，但必须在描述中说明增长原因 |
| > 150 MB | **失败**——阻止合并，需显式提升预算（改本文件 + 说明理由） |

设两级而非一级，是因为体积增长通常是渐进的：一级硬门禁会导致「刚好超一点」时有人去调阈值而不是查原因；警告区间能在增长变成既成事实之前先暴露出来。

### 6.3 校准点

上表是设计阶段的估算，**不是实测值**。libmpv 的实际体积取决于编译选项（启用哪些 demuxer/decoder/filter），浮动范围可能很大。

**强制校准**：M1 出口时用真实构建产物重新测量，并据此更新本节数值与门禁阈值。在此之前，CI 门禁按上述阈值执行但不阻塞 M0/M1 的开发。

### 6.4 可选组件（不进基础包）

| 组件 | 增量 | 分发方式 |
| --- | --- | --- |
| spider_python | ~30 MB | 按需下载 |
| spider_jvm | 0（依赖外部 JRE） | 用户自行安装 JRE 17+ |
| CEF（仅 Linux 嗅探） | ~100 MB | 按需下载，缺失时嗅探优雅降级 |

把 Python / JVM / CEF 移出基础包，是让基础包能守住预算的关键决定——否则光 CEF 一项就会让 Linux 版翻倍。
