# 06 · 插件系统

## 1. 定位

插件系统是 MiStream 的扩展边界。它要同时满足两个相互冲突的目标：**让第三方能扩展足够多的东西**，同时**让不可信代码无法伤害用户**。冲突的解法是：能力按类型分级，权限显式声明，运行时按类型隔离。

## 2. 插件类型

| 类型 | `type` | 能做什么 | 隔离方式 | 风险 |
| --- | --- | --- | --- | --- |
| 数据源 | `source` | 提供 Spider 实现（JS/Python/JVM/HTTP） | 独立运行时进程 | 中 |
| 主题 | `theme` | 提供设计令牌、配色、字体、圆角、图标集 | 纯数据，无代码执行 | **无** |
| 解析器 | `parser` | 把页面地址解析为直链 | 同数据源 | 中 |
| 运行时 | `runtime` | 提供 Python/JVM 等可选运行时二进制 | 独立进程 | **高**（原生二进制） |
| 工具 | `tool` | 字幕下载、元数据刮削、导入导出等辅助功能 | JS 沙箱 | 中 |

**主题插件零风险**是有意设计：它是纯 JSON/资源包，不含可执行代码，因此可以免审、免权限、一键安装。这让「换个皮肤」这种高频低危需求不必走重型流程。

## 3. Manifest

`manifest.json` 位于插件包根目录：

```jsonc
{
  "manifestVersion": 1,
  "id": "com.example.my-source",        // 反向域名，全局唯一，安装后不可变
  "name": "示例源",
  "version": "1.2.0",                   // SemVer，严格
  "type": "source",
  "description": "一句话说明",
  "author": { "name": "someone", "url": "https://..." },
  "homepage": "https://...",
  "license": "MIT",
  "icon": "assets/icon.png",

  "engine": {
    "minAppVersion": "1.0.0",           // 必填
    "maxAppVersion": null,              // 可选上界
    "runtime": "js",                    // js | python | jvm | http | none
    "runtimeVersion": ">=1.0.0"
  },

  "entry": "dist/index.js",             // 入口，相对包根

  "permissions": {
    "network": {
      "allow": ["*.example.com", "cdn.example.net"],   // 域名白名单，禁止裸 "*"
      "reason": "获取影片列表与播放地址"                  // 必填，安装时展示给用户
    },
    "storage": { "quotaMB": 5, "reason": "缓存分类数据" },
    "clipboard": { "read": false, "write": true, "reason": "复制分享链接" },
    "player": { "control": false, "reason": null },
    "notification": { "reason": "更新提醒" }
  },

  "contributes": {                       // 声明式贡献点
    "settings": [
      { "key": "quality", "type": "enum", "options": ["auto","1080p","720p"],
        "default": "auto", "label": "默认清晰度" }
    ],
    "commands": [
      { "id": "refreshCache", "title": "刷新缓存" }
    ]
  },

  "integrity": {
    "algorithm": "sha256",
    "hash": "<包内所有文件的 merkle 根>",
    "signature": "<作者私钥签名，可选>",
    "publicKey": "<作者公钥指纹，可选>"
  }
}
```

**校验规则**（安装时全部通过才允许继续）：

1. `id` 格式合法且未与已装插件冲突（同 id 视为升级）。
2. `version` 符合 SemVer；升级时新版本必须 > 旧版本，除非用户显式选择降级。
3. `engine.minAppVersion` ≤ 当前 App 版本 ≤ `maxAppVersion`。
4. `permissions.network.allow` 不得包含 `*`、裸 IP、私网地址。
5. 每项权限必须有非空 `reason`。
6. `integrity.hash` 与实际包内容一致。
7. `entry` 存在且在包内（禁止 `../` 逃逸）。

## 4. 权限模型

### 4.1 原则

- **默认拒绝**：manifest 里没声明的一律不给。
- **声明即上限**：声明了也不等于自动授予，安装时用户确认；高危权限（`runtime` 类插件、网络白名单过宽）需二次确认。
- **可撤销**：任何权限可在插件详情页随时关闭，插件必须能优雅处理被拒。
- **可观测**：插件详情页显示「最近 24 小时的网络请求数 / 存储占用 / 调用耗时」。

### 4.2 权限项

| 权限 | 授予后能做 | 强制约束 |
| --- | --- | --- |
| `network` | 通过宿主 `req` 请求白名单域名 | 仅 http/https；私网地址与 `file://` 一律拦截；单次响应 ≤ 20MB；并发 ≤ 4 |
| `storage` | 读写自己的 KV 命名空间 | 配额上限；无法访问其它插件的命名空间 |
| `clipboard` | 读/写剪贴板 | 读取需每次前台确认 |
| `player` | 控制播放器（播放/暂停/切集） | 仅当播放页处于前台 |
| `notification` | 发送应用内通知 | 频率限制（≤ 5 条/小时） |

**不存在的权限**（任何插件都拿不到）：任意文件系统访问、进程创建、原生代码加载（`runtime` 类插件除外，且走独立审核路径）、访问用户历史/收藏原始数据（只能通过明确的 API 读取当前上下文）。

## 5. 生命周期

```
   [未安装]
      │ install（下载 → 校验 → 解压到临时目录 → 权限确认 → 移入插件目录）
      ▼
   [已安装 · 禁用]
      │ enable                          ▲ disable（停止运行时，保留数据）
      ▼                                 │
   [已启用 · 未激活]────activate────►[激活]
      │  （首次调用时懒激活）      deactivate（空闲回收/App 退出）
      │
      │ uninstall（停止 → 删除文件 → 询问是否删除数据）
      ▼
   [未安装]
```

对应的插件侧钩子（可选实现）：

```js
export async function onActivate(ctx) { /* ctx: { storage, req, log, settings } */ }
export async function onDeactivate() {}
export async function onSettingsChanged(changed) {}
export async function onCommand(id, args) {}
```

**懒激活**是性能关键：装了 30 个源插件，启动时不能全部拉起。只有用户实际用到某个源（搜索勾选、浏览其分类）才激活。

## 6. 安装、更新与回滚

### 6.1 目录布局

```
%APPDATA%/MiStream/plugins/
├─ com.example.my-source/
│  ├─ 1.2.0/               # 版本目录，只读
│  │  ├─ manifest.json
│  │  ├─ dist/index.js
│  │  └─ assets/
│  ├─ 1.1.0/               # 保留上一版本用于回滚
│  └─ current -> 1.2.0     # 指针文件（Windows 用文本文件而非符号链接）
└─ data/
   └─ com.example.my-source/   # 插件数据，与版本目录分离，升级不丢
```

版本目录只读、数据目录独立 —— 这样升级 = 加一个新版本目录 + 改指针，回滚 = 改回指针，都是原子操作。

### 6.2 更新流程

```
检查更新（手动 / 每日一次）
 → 比对市场 index 中的最新版本
 → 若新版本要求更高的 minAppVersion → 提示先升级 App，不自动装
 → 若新版本请求了新权限 → 必须用户确认，不能静默
 → 下载 → 校验 hash/签名 → 解压到新版本目录 → 切换指针 → 重启该插件运行时
 → 激活失败 → 自动切回旧版本指针 + 通知用户
```

保留最近 2 个版本，更早的在下次启动时清理。

### 6.3 完整性与签名

- **hash 校验必做**：所有插件包安装前校验 sha256。
- **签名可选但影响标识**：签名有效的插件在 UI 显示「已验证」徽章；未签名的显示「未验证来源」警告。
- **不做强制签名**：会扼杀独立源作者，与生态目标冲突。用标识而非门槛来传达风险。
- `runtime` 类插件（含原生二进制）**必须签名**，且只接受官方仓库来源。

## 7. 插件与 Spider 的关系

两者不是同一层概念，容易混淆，明确如下：

- **Spider** 是一个接口协议（[05-Spider引擎](05-Spider引擎.md)），描述「怎么从源取数据」。
- **插件** 是一种分发与管理形态，描述「代码怎么装进来、有什么权限、怎么升级」。
- 一个 `type: source` 的插件，其 `entry` 实现的就是 Spider 接口。
- 但 Spider 不一定来自插件：从 TVBox 配置导入的源，是「配置驱动的 Spider」，走同样的运行时，但不经过插件的安装/权限流程——**它们的权限由导入配置时的一次性授权覆盖**。

这个区别要在 UI 上体现：「我的源」（来自配置）和「插件」（来自市场/本地安装）是两个入口，共享同一个源诊断面板。

## 8. 插件市场

### 8.1 索引协议

市场是一个静态 JSON 索引 + 分发在各自仓库的插件包，MiStream 官方不托管插件二进制：

```jsonc
// index.json
{
  "schemaVersion": 1,
  "updatedAt": "2026-01-01T00:00:00Z",
  "plugins": [
    {
      "id": "com.example.my-source",
      "name": "示例源",
      "type": "source",
      "description": "...",
      "author": "someone",
      "homepage": "https://github.com/...",
      "latest": {
        "version": "1.2.0",
        "minAppVersion": "1.0.0",
        "url": "https://github.com/.../releases/download/v1.2.0/plugin.zip",
        "sha256": "...",
        "size": 123456,
        "changelog": "..."
      },
      "verified": true,
      "tags": ["视频", "聚合"]
    }
  ]
}
```

### 8.2 合规约束（重申 [01-项目概述](01-项目概述.md) §6）

市场索引**只收录**：主题插件、工具插件、运行时插件，以及**源插件的代码仓库元数据**。

不收录、不分发、不索引：具体的站点配置、订阅地址、解析接口地址。源插件条目指向作者的代码仓库，具体源配置由用户自行获取。

### 8.3 多市场源

用户可添加自定义市场 URL。默认只有官方一个。添加第三方市场时明确提示「该市场的插件未经官方审核」。

## 9. 主题插件

因为无代码执行，格式最简单：

```jsonc
{
  "id": "com.example.midnight",
  "type": "theme",
  "version": "1.0.0",
  "theme": {
    "brightness": "dark",
    "tokens": {
      "color.primary": "#5B3FD6",
      "color.onPrimary": "#FFFFFF",
      "color.primaryText": "#A894FF",
      "color.surface": "#111318",
      "color.onSurface": "#E6E1E9",
      "radius.card": 12,
      "spacing.unit": 4,
      "font.family": "Inter",
      "font.scale": 1.0
    },
    "assets": { "background": "assets/bg.jpg" }
  }
}
```

令牌键名与取值范围由 [09-UI规范](09-UI规范.md) 定义。加载时对未知键忽略、对缺失键取默认值、对非法值（如颜色格式错误）回退——**主题永远不能让 App 白屏**。

加载后强制跑一次**对比度校验**（与内置主题用同一套断言）：任一前景/背景组合不达 WCAG AA 即拒绝该主题，回退内置主题并告知用户具体是哪个令牌不达标。主题作者可用 `mistream theme lint` 在本地提前发现。

## 10. 测试策略

| 层次 | 内容 |
| --- | --- |
| Manifest 校验 | 一组合法/非法 manifest 样本的单测，覆盖每条校验规则 |
| 权限沙箱 | 逃逸测试：越权网络、私网 SSRF、路径穿越、配额超限，全部必须被拦 |
| 生命周期 | 安装→启用→激活→升级→回滚→卸载 的完整状态机测试 |
| 原子性 | 模拟升级中途断电/进程被杀，验证不会留下半安装状态 |
| 主题健壮性 | 畸形主题包（缺键、错类型、超大图）不得导致崩溃 |
