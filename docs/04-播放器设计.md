# 04 · 播放器设计

## 1. 目标

一个**桌面级**播放体验：起播快、格式全、字幕好、控制细。播放能力是 MiStream 相对 TVBox 系客户端最直接的差异化，不能妥协。

## 2. 内核与封装

```
UI (PlayerPage / ControlBar / SubtitleMenu)
        ↓  只依赖抽象
PlayerEngine (abstract)          ← packages/player_engine
   ├─ MediaKitEngine   (一期实现)
   └─ NativeMpvEngine  (二期，dart:ffi 直连 libmpv client API)
        ↓
     libmpv
```

**为什么先 media_kit 再自研**：media_kit 能在几天内打通「Flutter 里出画面」这件最容易卡住的事（GPU 纹理共享、平台通道）。但它未暴露全部 mpv 选项（HDR tone-mapping、精细硬解回退、自定义 shader）。因此从第一行代码起就写在 `PlayerEngine` 抽象后面，二期换 `NativeMpvEngine` 时 UI 零改动。

抽象层的验收方式：**两个实现同时存在，跑同一套 `player_engine` 契约测试**。

## 3. PlayerEngine 接口

```dart
abstract interface class PlayerEngine {
  // 生命周期
  Future<AppResult<void>> initialize(PlayerConfig config);
  Future<void> dispose();

  // 媒体
  Future<AppResult<void>> open(MediaSource source, {Duration? startAt});
  Future<void> close();

  // 传输控制
  Future<void> play();
  Future<void> pause();
  Future<void> seek(Duration position);        // 钳制到 [0, duration]
  Future<void> setRate(double rate);           // 0.25 ~ 4.0，越界抛 ArgumentError
  Future<void> stepFrame({bool backward = false});

  // 音量
  Future<void> setVolume(double volume);       // 0 ~ 1.5，越界钳制
  Future<void> setMuted({required bool muted});

  // 轨道
  Future<void> selectVideoTrack(TrackId id);
  Future<void> selectAudioTrack(TrackId id);
  Future<void> selectSubtitleTrack(TrackId id);     // TrackId.disabled = 关闭
  Future<AppResult<void>> addExternalSubtitle(
    Uri uri, {String? title, bool select = true},
  );
  Future<void> setSubtitleDelay(Duration delay);
  Future<void> setAudioDelay(Duration delay);

  // 画面
  Future<void> setAspectRatio(AspectRatioMode mode);
  Future<void> setVideoFilter(VideoFilterSettings settings); // 亮度/对比度/饱和度/伽马
  Future<AppResult<Uint8List>> screenshot({bool withSubtitles = false});

  // 状态流
  Stream<PlayerState> get stateStream;        // idle/opening/buffering/playing/paused/ended/error
  Stream<Duration> get positionStream;        // 节流至 ~4Hz
  Stream<Duration> get durationStream;
  Stream<List<DurationRange>> get bufferedRanges;
  Stream<MediaInfo> get mediaInfoStream;      // 编码、分辨率、帧率、码率、色域、硬解状态
  Stream<PlayerLog> get logStream;
  Stream<PlayerError> get errorStream;

  // 同步快照（编排层做一次性判断用，不必为此订阅再取消一条流）
  PlayerState get state;
  Duration get position;
  Duration get duration;
  MediaInfo get mediaInfo;
  double get rate;
  double get volume;
  bool get isMuted;
  bool get isDisposed;
}

class MediaSource {
  final Uri uri;
  final Map<String, String> headers;   // UA / Referer / Cookie / Origin
  final List<Uri> externalSubtitles;
  final String? title;
  final bool isLive;                   // 决定缓冲策略，见 §6
  final DrmInfo? drm;                  // 保留字段，当前恒为 null（见合规边界）
}
```

`MediaInfo` 必须暴露**硬解是否真正生效**（mpv 的 `hwdec-current`），这是排查卡顿的第一手信息，要直接显示在 UI 的「播放信息」浮层。

### 3.1 失败怎么表达

[10-开发规范](10-开发规范.md) §3.4 要求可预期失败走 `Result`，而播放器的多数操作又不值得为此包一层。按三条收敛：

1. **返回 `AppResult`**：`initialize`、`open`、`addExternalSubtitle`、`screenshot`。这四个的失败由外部原因造成、可预期，且调用方**必须分支处理**——§7 的整条回退链就建立在「`open` 失败了，换下一个候选」之上。
2. **返回 `Future<void>`，只在调用顺序错误时抛 `StateError`**：其余传输控制。未 `initialize` 就调、`dispose` 之后再调，都是编程错误而不是可预期失败。
3. **走 `errorStream`**：播放过程中的异步失败（解码错误、网络中断、硬解降级）。它们不属于任何一次方法调用，没有返回值可挂。

当前实现不支持的能力（§4 能力矩阵里标 `—` 的项）返回 `UNSUPPORTED_PLATFORM` 的 `Err`，而不是抛异常或静默无操作。

### 3.2 流的订阅语义

所有 `Stream` 都是**广播流**，且**迟到的订阅者立即收到当前值**；`dispose()` 后全部关闭。

这一条必须钉死：播放页的组件是陆续挂载的，控制栏订阅 `stateStream` 时播放可能已经开始，拿不到当前值就会显示成「未播放」直到下一次状态变化——而正在稳定播放时，下一次状态变化可能是十分钟以后。

### 3.3 几处与早期草案的偏离

以下改动在 M1-a 落地时确定，起因是把接口真正写出来之后暴露的问题：

| 早期签名 | 现在 | 原因 |
| --- | --- | --- |
| `Stream<List<Duration>> bufferedRanges` | `List<DurationRange>` | 一个区间要起止两个值。扁平的 `Duration` 列表既分不清哪两个是一对，也表达不了「从哪儿到哪儿」——而 seek 之后同时存在多段不连续缓冲是常态 |
| `selectSubtitleTrack(TrackId? id)`，`null` = 关闭 | `selectSubtitleTrack(TrackId id)`，`TrackId.disabled` = 关闭 | `TrackId` 本身已带 mpv 的 `no` 语义，再叠一层 `null` 就有两种写法表达同一件事，调用方迟早两种都写 |
| `setMuted(bool muted)` | `setMuted({required bool muted})` | `avoid_positional_boolean_parameters`：调用点上的裸 `true` 读不出含义 |
| 全部 `Future<void>` | 见 §3.1 | 与 [10-开发规范](10-开发规范.md) §3.4 的 `Result` 要求冲突 |

## 5. 硬解策略

按平台优先级尝试，任一层失败自动降级并记录：

| 平台 | 优先级链 |
| --- | --- |
| Windows | `d3d11va-copy` → `d3d11va` → `dxva2-copy` → 软解 |
| macOS | `videotoolbox-copy` → `videotoolbox` → 软解 |
| Linux | `nvdec-copy` → `vaapi-copy` → `vaapi` → 软解 |

规则：

1. 默认 `hwdec=auto-safe`，只对白名单编码启用硬解。
2. 若首次解码在 3 秒内产生 ≥N 次解码错误，自动降级到软解并**在 UI 明确提示**，而不是静默黑屏。N 默认取 **3**（`HwdecFallbackPolicy.errorThreshold`）：再少会把偶发坏帧误判成硬解不可用，再多则用户已经看了好几秒花屏。这是可调值，不是从测量得来的常数。降级只触发一次、只提示一次——一段花屏会连报十几次错。
3. 用户可在设置里强制指定硬解方式（高级设置，带「可能导致黑屏」警告）。
4. 每个源/每个视频的降级结果写入本地缓存，下次同类内容直接用有效配置起播。

## 6. 网络流处理

- **请求头透传**：`playerContent` 返回的 UA / Referer / Cookie 必须原样传给 mpv（`http-header-fields`、`user-agent`、`referrer`），大量源依赖这个。
- **HLS**：交给 ffmpeg 的 hls demuxer；支持多码率自动/手动切换（`--hls-bitrate`）。
- **缓冲策略**：`cache=yes`，`demuxer-max-bytes` 按内容类型区分——点播 64MB，直播 16MB（低延迟优先）。
- **重连**：网络中断时按指数退避重连（1s/2s/4s/8s，上限 5 次），保持当前播放位置。
- **代理**：全局代理设置需同时作用于 Dio 与 mpv（`http-proxy`）。
- **DoH**：mpv 不支持 DoH，因此域名解析在 Dart 侧完成后以 IP + Host header 方式下发，或退化为系统 DNS（配置项）。

## 7. 播放编排（PlayUseCase）

播放器只负责「给我 URL 我就播」，选源、解析、重试的复杂度全在编排层：

```
选定 episode
 └→ for each flag(播放线路) in 优先级顺序:
      └→ spider.playerContent(flag, id)
           ├ parse == 0 → 直链，试播
           ├ parse == 1 → for each parser in parses(按 type/flag 过滤):
           │                 → 解析出直链，试播
           └ 无解析器命中 → 拉起 sniffer 嗅探
      └→ 试播判定：open() 后 8s 内未进入 playing 且无首帧 → 判失败
      └→ 失败 → 记录该 (source, flag, parser) 组合失败次数 → 下一个候选
 └→ 全部失败 → 结构化错误上报到 UI（哪个源、哪一步、什么错误码）
```

**关键**：失败必须给出可读原因（"源返回空地址" / "解析器超时" / "403 需要 Referer" / "编码不支持"），而不是笼统的「播放失败」。这是用户排障和源作者修源的唯一依据。

## 8. 续播与历史

- 每 5 秒或 seek 后写入播放进度（节流，避免写放大）。
- 记录粒度：`(mediaId, sourceId, episodeIndex, position, duration, updatedAt)`。
- 片头片尾跳过：支持按剧集全局设置，也支持单集覆盖。
- 播放完成阈值：进度 ≥ 95% 视为已看完，自动标记并连播下一集。
- 连播倒计时 5 秒，可取消。

## 10. 播放器 UI 要点

- **控制栏自动隐藏**：3 秒无操作隐藏，鼠标移动或按键唤出；暂停时不隐藏。
- **进度条**：显示缓冲区间、章节标记、悬停缩略图（需 mpv 二次实例抽帧，v1.0 目标）。
- **右侧抽屉**：剧集列表、播放线路(flag)切换、字幕/音轨、播放设置，切换不打断播放。
- **加载态**：区分「解析中」「连接中」「缓冲中」三种状态并显示当前步骤，避免用户面对无信息的转圈。
- **错误态**：错误卡片显示错误码 + 一句人话 + 「换个线路」「重试」「复制诊断信息」三个动作。
