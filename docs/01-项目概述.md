# 01 · 项目概述

## 1. 一句话定位

MiStream 是一个**现代化、跨平台、插件化的媒体聚合客户端**：兼容 TVBox 生态的配置与数据源协议，但在架构、播放内核、交互与工程质量上完全重做，而不是 TVBox 的移植或换皮。

## 2. 为什么做

现有 TVBox 系客户端的共性问题：

| 问题 | 现状 | MiStream 的应对 |
| --- | --- | --- |
| 平台受限 | 基本只有 Android / AndroidTV | Flutter Desktop 优先，Windows → macOS/Linux |
| 播放能力弱 | ijkplayer/ExoPlayer，HDR、AV1、Dolby Vision 支持参差 | libmpv 内核，硬解 + 现代编码 + 完整字幕栈 |
| 源逻辑与宿主耦合 | Spider 跑在主进程，一个源崩溃拖垮整个 App | Spider 独立进程沙箱 + JSON-RPC，崩溃隔离 |
| 无扩展规范 | 靠改代码、塞 jar | Manifest + 权限模型的插件系统，含 Spider SDK |
| 工程质量低 | 无测试、无 CI、无版本纪律 | Conventional Commits + CI/CD + 分层测试 |

## 3. 与 TVBox 的关系

**兼容什么**（协议层面）：

- TVBox 配置 JSON 的核心结构：`sites` / `lives` / `parses` / `flags` / `rules` / `wallpaper` / `spider` / `doh`
- `com.github.catvod.crawler.Spider` 的方法语义（`homeContent` / `categoryContent` / `detailContent` / `searchContent` / `playerContent` 等）
- drpy 系 JS 源所依赖的宿主 API 约定（`req` / `pdfh` / `pdfa` / `local` / 加解密工具集）
- 常见配置分发形式：明文 JSON、Base64、AES 加密体

**不兼容 / 不继承什么**：

- Android 专有运行时（`android.*` API、Dex 字节码、系统 WebView 行为）——见 [05-Spider引擎](05-Spider引擎.md) 的降级方案
- TVBox 的 UI 结构、焦点模型与配置项语义
- ijkplayer 的播放行为与 `ijk` 配置段（解析后忽略，或按需映射到 mpv 选项）

一句话：**MiStream 读得懂 TVBox 的配置，但不承诺跑得动 TVBox 的每一个二进制产物。**

## 4. 目标用户

1. **主用户**：桌面端（先 Windows）媒体消费者，自己持有或订阅配置源，追求画质与稳定性。
2. **次用户**：源作者 / 插件开发者，需要一套可调试、可测试、有文档的 Spider SDK。
3. **非目标用户**：手机端一次性使用者、期待「装了就有内容」的开箱即用用户。

## 5. 范围（Scope）

**做**：

- 播放：本地文件、HTTP(S)/HLS/DASH 流、自定义请求头、字幕、音轨、倍速、播放列表、续播
- 聚合：多源并发搜索、分类浏览、详情聚合、播放地址解析与嗅探
- 直播：`lives` 频道列表、分组、换台、EPG（后期）
- 个人数据：收藏、历史、下载、设置，本地优先，可选云同步
- 扩展：插件系统、主题系统、Spider SDK、插件市场
- 工程：自动更新、崩溃与日志、CI/CD

**不做**（明确排除，避免范围蔓延）：

- 不内置、不分发、不推荐任何内容源、订阅地址或站点配置
- 不提供 VIP 破解、付费内容绕过、DRM 解除能力
- 不做服务端内容托管、转码或 CDN
- 不做移动端（Android/iOS）——v2.0 之后重新评估
- 不做社交 / 评论 / 账号体系（云同步除外，且为可选自建）

## 6. 合规边界（硬约束）

这条边界决定产品形态，必须在设计阶段固化而非事后补：

1. **空壳交付** — 安装包内不含任何数据源、订阅地址、解析接口。首次启动引导用户自行导入配置。
2. **用户自带** — 所有源由用户主动输入 URL 或导入本地文件，App 不做任何形式的内置推荐或聚合目录。
3. **不绕过保护** — 不实现针对 DRM、付费墙、地域限制的绕过逻辑。嗅探能力仅作用于用户已导入源明确指向的页面。
4. **责任声明** — README 与首启引导中明确用户对其导入内容负责。
5. **插件市场同理** — 市场只索引「工具类 / 主题类 / 运行时类」插件；源插件仅索引其代码仓库元数据，不托管、不分发具体源配置。

## 7. 核心设计原则

1. **内核与外壳分离** — UI 不直接感知 Spider 的存在，只面向 Core 的领域模型。
2. **不可信输入假设** — 来自配置、源、插件的数据一律视为敌意输入：进程隔离、超时、限权、schema 校验。
3. **可降级** — 每个能力都有明确的失败路径（硬解失败 → 软解，嗅探失败 → 回退解析链，源超时 → 跳过而非阻塞）。
4. **本地优先** — 无网络也能用（本地文件播放、历史、收藏、已下载内容）。
5. **可观测** — 每次源调用都有结构化日志、耗时、错误码，用户可在「源诊断」面板直接查看。

## 8. 成功标准

| 维度 | v0.1 MVP | v1.0 |
| --- | --- | --- |
| 端到端 | 导入配置 → 搜索 → 详情 → 起播成功 | 同左，且直播 / 下载 / 插件可用 |
| 源兼容 | JS(drpy) + HTTP 两类运行时跑通主流源 | 覆盖 ≥90% 主流 JS 源 |
| 播放 | 1080p H.264/HEVC 硬解稳定播放 | 4K HDR / AV1 硬解，字幕音轨完整 |
| 稳定性 | 无 P0 崩溃 | 崩溃率 < 0.5%，源崩溃 100% 不影响主进程 |
| 首帧 | — | 本地 < 300ms，网络流 < 2s（P50） |
| 工程 | CI 绿灯，核心逻辑有单测 | 覆盖率 ≥60%，发布全自动 |
