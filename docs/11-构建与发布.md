# 11 · 构建与发布

> 本文补上工程里此前唯一空缺的一环：**本地怎么把 MiStream 构建出来**。
> 在此之前，全仓只有 `.github/workflows/release.yml` 提到构建命令，而那条流水线
> 的路径是错的（§7.3），照它做会直接卡住。构建相关的经验大多来自 2026-09-24
> 那次从零构建，逐条都实测过。

## 1. 前置条件

### 1.1 工具链

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Flutter | 3.44.8 stable | 基线锁在 `.tool-versions`，CI 的 `FLUTTER_VERSION` 与 [03-技术选型](03-技术选型.md) §2 要一起改 |
| Dart | 3.12.x | 随 Flutter 分发，不单独装 |
| Melos | `>=7.8.0 <7.8.2` | 根 `pubspec.yaml` 的 dev_dependency，上界原因见该文件注释 |
| Visual Studio 2022 | 含「使用 C++ 的桌面开发」工作负载 | Windows 构建必需 |
| Windows SDK | 10.0.19041 或更高 | 同上 |

### 1.2 初始化仓库

```bash
git clone <repository-url>
cd mistream_new          # 仓库根是 melos workspace，不是 Flutter app
dart pub global activate melos
melos bootstrap          # 会自动 git config core.hooksPath .githooks
melos run generate       # 生成 drift 代码（产物不入库）
```

**clone 之后必须先 `dart pub get` / `melos bootstrap`**。没解析依赖时
`dart analyze` 会报上万条 `uri_does_not_exist`（连 `package:flutter/material.dart`
都找不到），极易误判为代码损坏。

### 1.3 native 依赖

```bash
melos run libmpv:install      # 下载并校验 libmpv（锁版本 + SHA256）
melos run quickjs:install     # 校验 vendored QuickJS DLL
powershell -File tools/build_jvm_runtime.ps1   # 编译 spider_jvm_runtime.jar，需 JDK17
```

这些步骤把 native 依赖落到仓库根的 `build/`（`native_assets/`、`spider_js/`），
再由 CMake 拷进产物目录。**如果 `Release/` 里已经有 `libmpv-2.dll`、
`libquickjs.dll` 等，说明之前装过**，可以跳过。

`quickjs:install` 与 `spider-js:bundle` 在 CMake 里也会跑一次，是幂等的。

> ⚠️ `build_jvm_runtime.ps1` 与前两者**不同**：它不会在 CMake 里重跑，产物
> （`runtimes/spider_jvm/build/spider_jvm_runtime.jar`）也不入库。漏跑它的后果
> 不是「少个可选功能」，而是**整份 `csp_` 配置不可用** —— 0.1.0 的便携包就是
> 这么出厂的，见 §3.3。

## 2. 构建

```bash
cd apps/mistream
flutter build windows --release
```

### ⚠️ cwd 必须是 `apps/mistream`

仓库根**不是** Flutter app：根 `pubspec.yaml` 只有 `environment` / `workspace` /
`melos` 三块，`name: mistream_workspace`、`publish_to: none`，它是 pub workspace
根。真正的 app 是 `apps/mistream`（`name: mistream`，`version: 0.1.0+1`）。

在仓库根执行 `flutter build windows` 会报「不是 Flutter 项目」。
[10-开发规范](10-开发规范.md) §5.1 里画的流水线也应把这条当既定事实。

产物落在：

```
apps/mistream/build/windows/x64/runner/Release/
```

## 3. 产物结构

```
Release/                                    （约 88 MB）
├── mistream.exe                92 KB    ← 薄启动器，不是应用本体
├── data/
│   ├── app.so                 8.6 MB    ← Dart AOT 编译产物，真正的应用代码
│   ├── flutter_assets/                  ← 资源
│   └── icudtl.dat             845 KB
├── spider_js_runtime.exe      7.8 MB    ← Spider 子进程独立运行时（ADR-001）
├── runtimes/
│   └── spider_jvm/                      ← JVM 运行时（实验性可选组件，ADR-006）
│       ├── build/spider_jvm_runtime.jar   56 KB
│       └── libs/*.jar                     31 个依赖
├── flutter_windows.dll         21 MB
├── libmpv-2.dll                30 MB
├── libquickjs.dll / quickjs.dll / quickjs_wrapper.dll
├── sqlite3.dll / dartjni.dll / zlib.dll
├── media_kit_libs_windows_video_plugin.dll / media_kit_video_plugin.dll
├── volume_controller_plugin.dll
├── d3dcompiler_47.dll / libEGL.dll / libGLESv2.dll
├── vk_swiftshader.dll / vulkan-1.dll
└── native_assets.json
```

### 3.1 分发时必须整目录

`mistream.exe` 只有 92 KB，**单独拷走跑不起来**。Windows 版的 Dart 代码不在 exe 里，
而在 `data/app.so`，并且运行时还要同目录的一堆 dll。对外交付一律打包整个
`Release/` 目录（`release.yml` 里就是这么做的，见 §7.2）。

### 3.2 本地快速打包

```powershell
Compress-Archive -Path 'apps/mistream/build/windows/x64/runner/Release/*' `
                 -DestinationPath 'dist/mistream-windows-x64.zip' -Force
```

### 3.3 产物必须含 JVM 运行时（发布门禁）

```bash
dart run tools/check_jvm_runtime_bundle.dart \
  --bundle apps/mistream/build/windows/x64/runner/Release
```

断言 `runtimes/spider_jvm/build/spider_jvm_runtime.jar` 存在且非空、
`runtimes/spider_jvm/libs/` 下至少有一个非空 jar。任一不满足即 exit 1，
并打印修法。`release.yml` 与 `ci.yml` 的 `release-windows` 都跑这一步。

> 为什么需要这条门禁：`build/` 与 `libs/` 都不入库，jar 由
> `melos run jvm:build` 现场编译。于是「发布链忘了构建它」与「构建了但 CMake
> 忘了拷进产物」这两种失败**都不报错**，只是产物里少一个目录。0.1.0 的便携包
> 正是这样出厂的 —— 用户装上后 105 个 `csp_` 站点全部显示「暂不支持」，
> 而当时 CI 全绿。这条断言的意义不在于「检查一个文件」，而在于把静默降级
> 变成发布链红。
>
> CMake 侧对应的 install 规则是 `OPTIONAL` 的：没装 JDK 的本地 Debug/Release
> 构建不该被可选组件拦死，因此硬约束放在发布门禁这一层。

## 4. 环境坑

### 4.1 `ProgramFiles(x86)` 未定义会让工具链静默中断

Flutter 的 Windows 批处理包装需要读 `%ProgramFiles(x86)%`。缺失时报
`%PROGRAMFILES(X86)% environment variable not found` 并中断，**不会**给出
「这是环境变量问题」的提示。

```bash
env "ProgramFiles(x86)=C:\\Program Files (x86)" flutter build windows --release
```

注意 **bash 无法 export 带括号的变量名**（`not a valid identifier`）。需要时用一个
纯 ASCII 的 `.bat` 包一层，结果重定向到文件再读：

```bat
@echo off
set "PF86=C:\Program Files (x86)"
set "PROGRAMFILES(X86)=%PF86%"
cd /d <repo>\apps\mistream
flutter build windows --release
```

### 4.2 符号链接创建「假失败」

在某些虚拟化文件系统（如 I: 盘）上，Dart 的 `Link.create()` 会**链接建成但抛
`PathNotFoundException ... errno = 2`**。表现是构建卡在插件符号链接阶段、
每次报一个不同的插件名。

**每重试一次就多补一个链接**，所以循环跑到跨过该阶段即可：

```bash
until flutter build windows --release; do
  grep -q 'failed to create a link' build.log || exit 1
done
```

判定依据是错误文本里含 `failed to create a link`；其他错误不要重试。

### 4.3 `CMakeCache.txt` 指向别的目录

从另一份仓库拷贝过 `build/` 时，缓存里记的是旧路径，CMake 会报：

```
CMakeCache.txt ... is different than the directory <旧路径>
```

修法是**只删缓存，不删整个 build**：

```bash
cd apps/mistream/build/windows/x64
rm -f CMakeCache.txt && rm -rf CMakeFiles
```

### 4.4 慎用 `flutter clean`

`flutter clean` 会删掉整个 `apps/mistream/build/`，其中包括已经拷进来的 native
依赖。删之前先确认 §1.3 的安装步骤能重新拉到（网络受限时拉不到就构建不了）。

## 5. 合规扫描

发布前必须确认安装包内**不含任何源配置**（[10-开发规范](10-开发规范.md) §6.2 清单项）：

```bash
powershell -File tools/release_check.ps1 -BuildDir apps/mistream/build
```

扫描 `*.json` / `*.yaml` / `*.yml`，命中 `spider` / `api\.php` / `vod_pic` 即失败
（exit 1）。输出里会打印扫描到的文件数，便于确认不是空扫。

> `-BuildDir` **必须显式传**。脚本默认值就是 `apps/mistream/build`；早期的写法是
> 硬编码 `build`（相对 cwd），在仓库根跑时指向一个不存在或无关的目录，
> `Get-ChildItem -ErrorAction SilentlyContinue` 静默返回空集，扫描「通过」——
> 门禁形同虚设。现在目录不存在会直接失败。

## 6. 怎么判断手上的产物是新的还是旧的

产物是本地文件，**不带任何版本信息**。两条可靠办法：

### 6.1 看 `data/app.so` 里的特征字符串

在 `app.so` 里 grep 一个新引入的字符串，再用一个必然存在的串做对照：

| 标记串 | 编码 | 说明 |
| --- | --- | --- |
| `sanitizeJsonText` | UTF-8 | JSONC 支持 |
| `remote-debugging-port` | UTF-8 | CDP 嗅探 |
| `ResumePolicy` | UTF-8 | 续播决策 |
| `配置地址无效` | **UTF-16LE** | 配置 URL 前置校验 |
| `mistream` / `flutter` | UTF-8 | 对照组，确认能读到该二进制 |

**⚠️ 中文串必须按 UTF-8 与 UTF-16LE 两种编码各搜一次。** Dart AOT 把中文字面量
存成 UTF-16LE，只搜 UTF-8 会全部未命中，从而误判「产物里没有这段代码」——
2026-09-24 就因此把「旧产物不含中文域名规范化」写进了结论，实际它就在里面。
**优先挑 ASCII 标记串做判据。**

### 6.2 多份拷贝先比 md5

同一份产物被 `cp` 到多处时 mtime 各不相同，但 md5 一致。2026-09-24 实测
`mistream` / `_mistream_backup_20260920` / `_release_backup_tmp` 三处的
`data/app.so` md5 完全相同（`43fd5b6da693`），一次就确认了「9-05 之后根本没构建过」，
省掉一轮猜测。**mtime 单独看会误导**，`cp` 会刷新它。

## 7. CI 与发布

### 7.1 `ci.yml`（PR / main）

`lint` / `arch` / `commitlint` / `test`（三平台矩阵）/ `build-check`（三平台 debug）
/ `release-windows`（Release 包链 + spider_js 握手 + JVM 运行时门禁 + 上传产物）。
其中 `build-check` 与 `release-windows` 的 `working-directory` 都是 `apps/mistream`。

`release-windows` 用 `actions/setup-java@v4` 钉住 **JDK 17** 再跑
`melos run jvm:build`。钉版本不是洁癖：`build_jvm_runtime.ps1` 用
`--release 17` 固定了字节码目标，但编译器的版本仍会影响产物，而 ADR-006 要求
用户自行安装的是 JRE 17+ —— 编译环境与运行环境必须对齐。

### 7.2 `release.yml`（tag `v*`）

构建 Windows Release → 校验产物包链（`tools/check_spider_js_bundle.dart --smoke`）
→ 校验产物含 JVM 运行时（`tools/check_jvm_runtime_bundle.dart`）→ 合规扫描 →
打包整目录 → 创建**草稿** Release（人工确认后发布）。

只上传一个 zip，不上传裸 `mistream.exe`——理由见 §3.1。

### 7.3 已修：`release.yml` 的路径 bug（2026-09-24）

修复前的写法：

```yaml
- name: 构建 Windows
  run: flutter build windows --release                       # ← 在仓库根跑
- name: 创建草稿 Release
  with:
    files: build/windows/x64/runner/Release/mistream.exe     # ← 相对仓库根
```

两处都错：仓库根不是 Flutter app，且产物实际在 `apps/mistream/build/...`。
这条流水线**大概率从未成功跑过**——与 [ROADMAP](../ROADMAP.md) M10 的
「出口标准尚未勾选，因为均需真实 tag 跑通」吻合。

修法：加 `working-directory: apps/mistream`（与 `ci.yml` 对齐）、合规扫描显式传
`-BuildDir`、并新增打包步骤。**改动尚未在真实 tag 上验证过**，M10 的出口标准
仍需要在真 tag 上跑通才能勾。
